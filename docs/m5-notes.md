# M5 작업 노트

> `docs/m5-plan.md`를 실행하면서 생긴 기록을 모은다.
> 규칙의 원본은 `docs/rulebook-v3.md`이며, 이 문서는 구현 과정의 기록일 뿐 규칙을 정의하지 않는다.

## 착수 전 확정 (2026-10-25)

M4와 함께 무인 진행으로 승인받았다 (`docs/m4-plan.md` 11절). M5에 걸린 결정은 다음과 같다.

| 항목 | 결정 |
|---|---|
| 범위 | 에셋 적용·프리로드·연출 + **서버 배포 빌드 설정**. 세이브/불러오기, 호스팅·실제 배포, OAuth 프로덕션 게시는 후속 (m5-plan 4절) |
| 소리·진동 | 넣지 않는다 (m4-plan 11.1 a·b) |
| 프리로드와 시작 | 프리로드가 끝나지 않아도 시작을 막지 않는다 (m4-plan 11.1 c) |
| 연출 시간 | `constants/motionTiming.ts` 한 곳. 룰북 §19 단계 시간 안에서만 (m4-plan 11.1 g) |
| 추가 의존성 | web `sharp`(이미지 변환 스크립트 전용), server `esbuild`(배포 빌드) |

## 자동 확인 결과 (2026-10-25)

| 확인 | 결과 |
|---|---|
| `assets.spec` | Display가 로비에서 11종을 모두 받고 디코드한다. 게임이 시작된 뒤 Display·Controller 어느 쪽도 **처음 받는 이미지가 없다** |
| `motion.spec` | 단계에 들어선 순간 돌고 있는 끝이 있는 애니메이션이 모두 그 단계의 룰북 시간 안에서 끝난다. 축소 모드에서는 끝이 있는 움직임이 없다 — 첫 실행에서 M4의 `NarrationPanel`·`HostBar`에 축소 규칙이 없던 것을 잡아 더했다 |
| `redMessage.spec` | 요괴화 탈을 얹은 뒤에도 진짜·가짜의 DOM·스타일·픽셀·표시 시간이 같다 |
| `layout.spec`·`regression.spec` | 에셋이 붙은 화면에서도 세이프존·캠 자리·대비 통과 |
| 운영 번들 | `NODE_ENV=production`으로 `node dist/index.js` → `/healthz` 정상, 토큰 없는 방 생성 401. 같은 환경에서 e2e 번들은 시작을 거부한다 |
| 번들된 e2e 서버 | `E2E_BUNDLED=1`로 스모크·정적 규칙 2개·인간 1명 한 판·비상 5개·부적 선착순 **모두 통과**. 부적 선착순은 처음에 8판 동안 경합이 안 생겨 실패했다 — 대역 정책(`useAll`이 부적을 회복에 먼저 써 버림) 탓이라 `risky`로 바꿨다 |
| 커버리지 (32판) | 머물지 않는 2단계를 뺀 단계 전부, 엔딩 5종(무사귀환·영원한 미로 제외), 루트 3종, 개입 3종, 부적 경합 2건(진 쪽 거절 1건) |
| 서버 테스트 | 437건 통과 |
| 빌드 산출물 | 이미지 합계 약 4.2MB (원래 `introMask.png` 한 장이 7.7MB) |

## 계획 변경

`docs/m5-plan.md`와 달라진 결정.

| 날짜 | 항목 | 계획 | 실제 | 이유 |
|---|---|---|---|---|
| 2026-10-25 | M5-1 에셋 이름 표기 | `assetPlaceholder.ts`를 지우고 이름은 `assetLabel.ts`로 옮긴다 | `assetLabel.ts`를 만들지 않았다 | 이름을 띄우던 곳은 탈 자리의 임시 카드뿐이었고, 이미지가 붙으면서 이름 카드가 필요 없어졌다. 쓰는 곳이 없는 상수 파일을 만들지 않는다 |
| 2026-10-25 | M5-1 `introMask` | webp 변환 | 768px 폭 webp(**16KB**, 원본 7.7MB). 원본 PNG는 그대로 두되 아무 곳도 import하지 않아 빌드 산출물에 들어가지 않는다 | 랜딩에서 192px 폭으로만 보인다. 4배 해상도 화면까지 덮는 크기다 |
| 2026-10-25 | M5-3 주사위 카운트업 | 숫자 카운트업 | 1부터 서버 값까지 같은 간격으로 올린다(0.6초). **무작위 숫자를 굴려 보이지 않는다** | 화면이 굴림 값을 만드는 것처럼 보이면 안 된다(아키 §9.3). 놓쳐도 마지막 그림은 스냅샷 값이다 |
| 2026-10-25 | 커밋 단위 | M5-1~M5-6을 단위마다 커밋 | **M5-1~M5-4를 한 커밋, M5-5를 한 커밋**으로 담았다 | 긴 e2e를 백그라운드로 돌리는 동안 이어서 만들어, 같은 컴포넌트(`StageBackground`·`MaskApparition`)에 M5-1(이미지)과 M5-3(움직임) 수정이 섞였다. `package-lock.json`의 sharp·esbuild 변경은 M5-5 커밋에 함께 들어간다. 아키 §3의 배포 빌드 문장은 M4-7 커밋에 먼저 들어갔다 |
| 2026-10-25 | M5-4 붉은 메시지 | 요괴화 탈 + 연출 | 등장 움직임은 한 번뿐(0.7초)이고 반복하지 않는다 | 반복 움직임이 있으면 같은 cue라도 보는 순간마다 그림이 달라, 진짜·가짜 동일성 검사(픽셀 비교)가 흔들린다 |

## 제안

| 날짜 | 항목 | 내용 | 상태 |
|---|---|---|---|
| 2026-10-25 | 아이템 아이콘 크기 | 폰은 아이템 2종 + 요괴화 탈(약 1MB)을 미리 받는데, 아이템은 인벤토리에서 18px 아이콘으로만 쓴다. 128px webp 축소본을 따로 두면 폰이 받는 양이 크게 준다. 다만 옥비녀는 진엔딩 Display에서 크게도 쓰므로 키 하나에 크기별 주소가 둘이 된다 | **보류 — 실기 후 판단** (2026-10-25) |
| 2026-10-25 | 배경 이미지 해상도 | 배경 4종은 1248×832(3:2)다. 1920 폭 방송 화면에서는 1.5배 넘게 확대되고 위아래가 잘린다. 16:9·1920 폭 이상으로 다시 뽑으면 화질과 구도가 모두 나아진다 | **사람이 에셋을 다시 만든다** (2026-10-25). 같은 파일명(`src/assets/images/backgrounds/*.jpg`)으로 덮어쓸 예정이라 코드 변경은 없다 — `ASSET_URL`이 같은 경로를 import한다 |
