### 결과 표시 3초가 시뮬 소요 시간에 준 영향 (2026-09-19)

`--humans all --games 100`을 **같은 시드로 체류 0초·3초 두 번** 돌려 차이만 뽑았다.

| 인간 | 평균 소요 (체류 0초 → 3초) | 타임오버 | 시계 0 도달 | Phase 2 종료 평균 잠식 | 배신자 평균 |
|---|---|---|---|---|---|
| 0명 | 52분 55초 → 53분 33초 | 0.0% → 0.0% | 89.0% → 89.0% | 70.0% → 70.0% | 0.00 → 0.00명 |
| 1명 | 26분 34초 → 27분 13초 | 0.0% → 0.0% | 13.0% → 13.0% | 72.2% → 72.2% | 0.00 → 0.00명 |
| 2명 | 32분 10초 → 32분 49초 | 0.0% → 0.0% | 18.0% → 18.0% | 68.9% → 68.9% | 0.45 → 0.45명 |
| 3명 | 35분 54초 → 36분 32초 | 0.0% → 0.0% | 23.0% → 23.0% | 71.7% → 71.7% | 0.75 → 0.75명 |

- **늘어난 시간은 판당 38~39초**다. 이벤트 13개 × 3초에 입력 유예 0.3초씩이 붙은 값이다
- **잠식도·배신자·엔딩·타임오버 비율은 한 자리도 바뀌지 않았다.** 체류는 난수를 쓰지 않아
  판의 전개가 그대로다. 밸런스에 영향이 없다는 판단(계획 9절 3번)이 측정으로 확인됐다
- 위 표는 100판 기준이라 `docs/m2-notes.md`의 300판 표와 직접 비교할 수 없다. **M2 측정 기록은 그대로 둔다**

## 계획 변경

`docs/m4-plan.md`와 달라진 결정.

| 날짜 | 항목 | 계획 | 실제 | 이유 |
|---|---|---|---|---|
| 2026-09-19 | M4-1 표기 사전 | 사전 6개 (`brotherLabel`·`attributeLabel`·`judgmentLabel`·`variantLabel`·`endingLabel`·`rejectionLabel`) | `phaseLabel`·`stepLabel` 2개를 더 만들었다 | M4-1의 끝나는 조건이 "자리표시자에 **단계**·남은 시간이 뜬다"인데 단계·Phase의 한국어 표기가 목록에 없었다. M4-2의 `ClockHud`도 Phase 표기를 요구한다. 다른 사전과 같은 규칙(shared 상수 → 한국어)을 따른다 |
| 2026-09-19 | M4-1 cue 큐 | `useCueQueue.ts` 하나 | `constants/cueChannel.ts`를 더 만들었다 | cue를 **어느 자리에 연출할지**(덮개·토스트·장면·모달)는 스토어(쌓고 버리기)와 컴포저블(꺼내 쓰기)이 함께 봐야 하는 값이다. 두 곳에 문자열을 흩뿌리지 않고 `CueKind → CueChannel` 표 하나로 고정했다. 상수 하나에 파일 하나라는 규칙을 지킨다 |
| 2026-09-19 | M4-1 소켓 수명 | 방 진입·이탈에서만 `connect`·`disconnect`를 부른다 | 진입은 `useRoomSocket`이, **이탈은 라우터 가드**(`roomSocketGuard`)가 한 곳에서 한다 | 이탈을 화면의 `onBeforeUnmount`에 두면 로비 → Display 이동에서 "이전 화면 정리"와 "다음 화면 연결"의 순서에 결과가 달라진다. 목적지의 방 코드를 보고 판단하면 순서에 기대지 않는다 (계획 4.1) |
| 2026-09-19 | M4-4 토스트 | `WhisperToast`는 M4-5 | **`CueToast`를 M4-4에 앞당겨 만들었다.** 귓속말뿐 아니라 토스트 자리를 쓰는 cue 전부(튜토리얼 부적 지급, 개입 수단 사용, 연습 설명)를 하나가 받는다 | 계획 10절 6번은 **M4-4 뒤에 8절 1~5번을 확인**한다고 적었는데, 1번(튜토리얼 부적 지급 안내)과 5번(귓속말)은 폰에 띄울 자리가 M4-5에 있었다. 계획 안에서 어긋난 지점이라 확인이 가능하도록 앞당겼다. 자리를 나누지 않은 이유는 **귓속말만 다르게 보이면 "저 사람이 귓속말을 받았다"가 새기 때문**이다 (룰북 §17). 계획 4.3도 토스트를 "겹치지 않게 순차 표시" 한 자리로 적었다 |
| 2026-09-20 | 비공개 판정의 판정자 | 투영을 늘리지 않는다 (9절 4번에서 승인된 3가지뿐) | **`PublicView.rollerSeat`을 더했다** (9절 14번 확정) | 판정자는 채택 선택지의 속성 태그로 이미 공개된 정보라 새로 새는 것이 없다 (룰북 §3.1, §6.4). 비공개 판정은 잠식도 +10%를 내고 진실·거짓을 모르는 정보를 받는 장면이라 판정자가 직접 굴려야 긴장이 산다. 은닉 테스트 2건으로 "판정자는 공개, 주사위·기준·성패는 비공개"를 고정했다 |
| 2026-09-19 | M4-4 `RESOLUTION` 화면 | 계획 5절은 "결과 문장과 적용 내역을 겹쳐 표시" | Display에 **채택 선택지 문장과 판정 결과**만 3초 보여준다 | 적용 내역(누가 몇 % 올랐는지)은 투영에 없다. 잠식도는 본인에게만 가는 값이라(룰북 §17) 애초에 Display에 올 수 없고, 공개해도 되는 항목은 이미 `notices`로 온다 |
| 2026-09-19 | M4-1 개발용 시계 단축 | 서버에만 둔다 (9절 12번) | web의 `/menu?clock=<분>`에서도 실어 보낸다 | 서버에만 두면 사람이 짧은 판을 돌리려고 토큰을 들고 curl을 써야 한다. 8절 15번(타임오버 확인)이 그 기능을 쓰는 확인 항목이다. 화면에 버튼은 두지 않는다 — 운영에서 쓰는 기능이 아니고, 서버가 개발 환경이 아니면 값을 무시한다 |
